# ADR-0026: 생성과 보정의 분리 — 새로움에서 출발하는 테제

상태: accepted (2026-10-30). ADR-0025(구조 가설 트랙)의 **생성 방식**을 바꾼다. 테이블·stage·근거 루프는 그대로다.

## 문제
10/29 밤 첫 테제 세션(사람이 돌림)의 결과 6개 중 4개가 stage 2 였다. stage 2 는 정의상 "공급 반응이 보인다" — 시장이 이미 읽을 시간이 있었다는 뜻이다. 사용자의 판정: "미래의 테제를 찾는 관점보다는 과거 테제만 수집한 느낌". 원인은 넷이다.
1. **입력이 뉴스였다.** 지난 3주 `issues` 테이블에서 출발했다. 뉴스에서 출발하면 시장이 지금 읽고 있는 것밖에 안 나온다. ADR-0025 결정 5(출처를 수요가 생기는 곳으로)를 써 놓고 지키지 않았다.
2. **벤치마크가 생성을 지배했다.** "닮은 과거 사례" 를 먼저 고르면 지난 사이클의 다음 판만 찾는다. 고쳐 쓴 출발점("지난 0~6개월의 사용 방식 변화 + 알려진 시차 구조")도 여전히 과거 패턴이었다 — 사용자의 두 번째 지적.
3. **벤치마크 자체가 당시엔 전례 없는 것이었다.** 2022년 말 "메모리 슈퍼사이클" 템플릿은 커머디티 DRAM 을 가리켰지 HBM 을 가리키지 않았다. HBM 테제는 새 워크로드(트랜스포머 추론) × 기존 제약(대역폭 벽) 의 새 조합이었고, InP 체제의 절반은 수요가 아니라 중국의 갈륨·인듐 수출통제라는 새 이슈였다. 새 테제는 새 데이터·새 기술·새 이슈에서 나온다.
4. **모델도 과거로 학습된 패턴 매처다.** 모델에 "다음 HBM 은 무엇이냐" 고 물으면 유추가 나온다. 시스템이 날것의·이질적인·선행 시간이 긴 입력을 먹이고 메커니즘 질문을 던져야 보완된다.

## 결정
1. **생성과 보정을 분리한다.** 벤치마크(`research/benchmarks/regime_cases.json`)는 크기·시차를 **보정**하는 데만 쓴다. `benchmark` 는 선택 항목이 되고, 테제마다 `novelty` 를 적는다: `new_technology`(온톨로지에 없던 기술·부품) · `new_data`(2년 전엔 없던 데이터가 처음 보여주는 것) · `new_issue`(규제·수출통제·관세·사고) · `new_structure`(거래·계약 구조의 변화 — 고객의 공급사 선투자 같은) · `analog`(과거 사례의 재현). `novelty_reason` 한 줄 — 왜 전례가 없는가(또는 어떤 전례의 재현인가). 전례 없는 테제는 불확실성을 크게 적되 **살려 둔다**.
2. **세 입구와 네 질문.** 입구: 새 기술(온톨로지 잔차), 새 데이터, 새 이슈·구조. 공통 생성 질문은 유추가 아니라 메커니즘이다 — (a) 이것이 10배가 되면 무엇이 묶이나 (b) 무엇이 무가치해지나 (c) 가격 결정력이 어디로 옮겨가나 (d) 누가 비용을 떠안나. 답이 온톨로지의 노드로 그려지면 테제 후보, 그려지지 않으면 **먼저 온톨로지 패치**(새 노드) 다.
3. **선행 시간이 긴 출처로 바꾼다.** 출처마다 제품 수량에 앞서는 시간이 다르다 — 논문 2~4년 · 표준·컨소시엄 1~3년 · 학회 프로그램 1~2년 · 채용 공고 6~18개월 · 추론 플랫폼 릴리스·모델 API 변경 3~12개월 · 공시·컨콜 0~6개월 · 뉴스 0. 테제 작업의 **1부는 약한 신호 스캔**이고 뉴스는 입력에서 뺀다. `issues` 테이블은 거꾸로 "이미 읽힌 것" 을 걸러내는 필터로만 쓴다.
4. **알아차림과 이론화를 분리한다.** 스캔의 산출은 테제가 아니라 관찰이다 — `ideas.weak_signals`: 용어, 종류 추정, 출처 유형·선행 개월, 처음·마지막 본 날, 본 횟수, 출처들, 메커니즘 한 줄, 늘리는 것·줄이는 것, 매핑된 노드(없으면 null), 상태(watch · promoted · dropped). **승격 규칙**: 서로 다른 출처 유형 둘 이상에서 만나거나 3주 안에 재등장하면 테제 후보. 지금은 둘이 한 번에 일어나서 아는 패턴으로 수렴한다.
5. **수집기 잔차 큐.** 수집기의 LLM 선별이 node_catalog 에 없는 기술·부품·소재·표준 용어를 `unmapped` 로 함께 내고, `ideas.unmapped_terms` 에 쌓는다(용어, 종류 추정, 처음·마지막 본 날, 횟수, 이슈 key 들). 주간 온톨로지 패치가 여기서 새 노드 후보를 뽑는다. 온톨로지 노드의 나이(패치 날짜) 대비 간선 증가 속도를 새로움 지표로 본다.
6. **신규 테제는 stage 0~1 만.** 처음 저장할 때 stage 2 이상이면 `kind = regime`(체제 기록) 으로만 받는다 — 사슬의 맥락·리포트의 배경으로는 쓰되 발굴 대상이 아니다. 기존 테제는 갱신으로 stage 를 올린다. 10/29 의 stage 2 네 개(packaging_capacity_premium_2026 · rack_power_800vdc_2027 · onsite_power_grid_bypass_2026 · inp_laser_supply_regime_2026)는 `regime` 으로 옮긴다.
7. **필수 항목 추가** (`kind = thesis` 에만): `what_market_misses` 한 문장, `lag_months`(벤치마크 또는 추정 + 근거), `first_signal`(첫 공급망 신호가 나타날 지표·장소·예상 시점), `quiet_check`(수혜 기업마다 6/12개월 주가 변화·최근 이익 컨센서스 수정 — 이미 움직였으면 테제가 아니라 기록).
8. **T-3 재정의.** point-in-time 재현의 질문은 "템플릿이 2022-11 에 HBM 을 맞혔나" 가 아니라 "2022-11 의 약한 신호 스캔(논문·표준·채용·플랫폼 릴리스)이 HBM·CoWoS 를 잔차로 잡았나" 다.
