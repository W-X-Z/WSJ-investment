# ADR-0022: 가설 검증 루프 — 2단계 생성과 예측 채점이 움직이는 ★

상태: accepted (2026-10-29). 사용자: "가설을 검증하고 더 조사하는 방향성은 좋은 것 같아." ADR-0020 의 '남은 일' 두 가지를 구현한다.

## 문제
- 아이디어를 한 번에 쓰면 LLM 은 근거가 가장 많은 기업으로 수렴한다 — 시장이 이미 아는 것. 첫 수동 실행(10/29)의 새 가설 3건 중 2건은 수주·법설회가 이미 난 기업이었다.
- 예측(watch)을 채점은 하지만 그 결과가 ★ 에 닿지 않았다. ★ = 검증 단계(ADR-0020)라면 적중이 ★ 를 올리고 반증이 가설을 버려야 한다.
- 조사(원문 확인)가 '기업 소식 ★2+' 에서만 출발해, 가설이 가리키는 곳(아직 조용한 기업의 IR·고객 발표)을 보지 않았다.

## 결정
1. **2단계 생성** (`wsj.ecosystems.hypotheses`): 같은 입력으로 먼저 가설 후보 8~15개를 한 줄씩 연다 — 변화(S 근거) → 그래프 경로 → 미국·한국 기업 → 숫자·시점 → 왜 시장이 모르나 → 반증 조건 → 확인할 것.
   엔진이 검사(근거 id·노드·시장 범위)하고 채점한다: 구체·대담·반증 가능·설명력 각 0~3점(12점), 경로 끊김(2단계 넘게)·활성 아이디어와 기업 중복은 감점.
   상위 max_ideas 개를 고른다(기업당 1개, 생태계마다 1개 이상, 5점 미만 제외). 고른 후보마다 조사 계획(확인할 것·반증 조건·경고·이미 아는 소식)을 낸다.
2. **조사가 가설을 따른다**: 예약작업은 조사 계획대로 원문을 확인해 기업 소식(`put_company_events`, 새 행 가능)·관측치로 저장한다 → 2차 입력에 근거로 들어온다.
   확인 못 한 것은 추론 단계로 남긴다 — 조사가 가설을 막지 않는다.
3. **2단계 작성**: 새 아이디어는 고른 후보에서 쓴다(`hypothesis: "H3"`, 판단에 후보 점수·순위를 기록). 후보 밖은 조사에서 새 변화가 드러났을 때만.
4. **예측 채점이 ★ 를 움직인다** (`wsj.ecosystems.verification`, 실행 끝에 자동): hit = 적힌 조건이 그대로 일어났다(strengthen 의 hit 는 적중, weaken 의 hit 는 반증 성립).
   적중 1 → ★2, 적중 2 → ★3(기존 문턱 — 30일 안 기업 직접 근거·근거 점수 7+ — 충족 시, 아니면 ★2), 반증 성립 → 종료(같은 실행에서 고쳐 쓴 행은 ★1 로 유지), strengthen 빗나감 2 → ★1.
   적중이 있는 가설은 근거 점수가 낮아도 ★1 로 내리지 않는다. 기록은 `assessment.verification`, 입력의 `existing.verification` 으로 LLM 에게도 보인다.
5. 화면: 예측 절에 적중·빗나감·반증·대기 요약과 ★ 규칙 한 줄, weaken 항목의 hit 는 '반증 성립'.

## 결과
- 매일 흐름: 1차 입력 → **가설 후보(1단계) → 선택·조사 계획 → 조사** → 2차 입력(고른 후보 포함) → 아이디어(2단계) → 검증(예측 채점 → ★) → 저장.
- 세션이 쓰는 파일이 둘 늘었다(hypotheses.json, 엔진이 만든 selected.json·research_plan.json). API 모드(`--model`)는 아직 1단계를 자동으로 부르지 않는다 — 다음 PR.

## 남은 일
- API 모드에서 1단계 LLM 호출 자동화. 후보 점수와 실제 적중률의 상관을 주간 작업에서 점검해 채점 가중을 보정.
- 과거 사례(ADR-0011)로 가설 품질 교정.
