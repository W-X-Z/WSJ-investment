# ADR-0017: 스스로 판단하고 개선하는 리서치 시스템

- 상태: 채택 (2026-10-28)
- 관련: ADR-0012(온톨로지), ADR-0014(이슈 피드), ADR-0016(투자 아이디어 피드)

## 1. 맥락 (사용자, 2026-10-28)
"이 프로젝트는 더 많은 데이터와 더 많은 개선이 필요하다. 스스로 개선을 진행하면서 좋은 투자 기회를 발굴하고 판단할 수 있는 시스템을 만들어 달라."

같은 날 점검에서 드러난 것:
- **데이터**: 기업 소식의 90% 가 뉴스(공시 101/976). 대만 월매출 지표는 최신 1개 시점만 있어 가속·둔화를 못 봤고, FRED 구리·알루미늄은 0건(Actions 에서 응답 없음). 이미 쌓인 가격(85종목)·내부자 거래·공매도 데이터는 아이디어에 쓰이지 않았다.
- **온톨로지**: 병목 64개 중 11개가 2단계 안에 상장사로 이어지지 않았다(기판 생산능력·ABF·프로브카드·메모리 테스터·TC 본더·MLCC 등). 노드 없는 이슈 5/30 — 10/19 "광섬유 현물가 수배 급등"은 그래프에 광섬유 공급 병목 노드가 있는데도 태깅되지 않아 아이디어 후보가 0건이었다. 같은 날 찾은 수혜 기업(志聖·群翊·대한광통신·Sterlite 등)은 그래프에 없었다.
- **판단**: ★ 1~3 만 있고 왜 그 별인지의 분해, 노출 순도(그 사업이 매출의 몇 %인지), 이미 움직인 폭, 날짜 있는 확인 일정이 없었다. 확인 일정이 맞았는지 채점하지 않아 무엇이 통하는지 배울 수 없었다.

## 2. 결정

### 2-1. 데이터 더 넓게
1. **가격** (`wsj.ecosystems.prices`): 그래프 상장사 313곳의 일봉 — 미국(Nasdaq API), 대만(TWSE·TPEx), 한국(Naver), 중국·홍콩(Tencent), 일본(Kabutan). 매 실행 증분 + 남은 시간만큼 1년 백필. 가격은 **근거가 아니다** — '이미 움직인 폭'과 '설명 안 된 급변'(조사 단서)에만 쓴다.
2. **대만 월매출**: 그래프의 대만 상장사 전부(17 → 63곳)를 이력용으로 저장, '가속'(당월 YoY − 누적 YoY ≥ 25%p) 신호.
3. **FRED**: 브라우저 UA 가 봇으로 막혀 있었다 → 평범한 UA. 그래도 막히면 매일 작업(세션)이 받아 넣는다(`indicators fred-sql`).
4. **내부자 장내 매수** (Form 4, $10만 이상, 10b5-1 제외)를 기업 소식(filing)으로.
5. **병목 상태 관측치** (`obs:` 지표, `ideas.put_observations`): 원문에서 확인한 숫자 — 가격 배수·리드타임·가동률·재고·수주잔고·평균단가·증설 완공 시점 — 를 병목 노드에 시계열로 붙인다. 매일·매주 예약작업이 기록한다.

### 2-2. 온톨로지 끊긴 곳 없이
1. 11개 병목을 라벨이 이미 말하던 공급사로 이었다(근거는 기존 간선과 같은 출처의 발췌). 검증 규칙: **병목은 mitigated_by → 부품·소재 → offered_by 로 2단계 안에 상장사가 있어야 한다**(어기면 CI 실패).
2. 광섬유·광케이블, 게르마늄 공급(→ 광섬유 병목), 기판 공정장비, 중국 밖 InP 기판, 계통연계 대기열 → 가스엔진·연료전지를 더했다.
3. 그래프 변경은 `graph_patches/pYYYYMMDD_*.py` 로만 — 멱등이고, 근거·등급이 코드에 남고, 적용 후 검증이 실패하면 파일을 쓰지 않는다.
4. 이슈 태깅 안전망: 선별 모델이 노드를 비우면 기사 어휘 태그(별칭·현지어)를 쓴다.

### 2-3. 판단 (`wsj.ecosystems.assess`)
- **10점 근거 점수** = 기업 직접 근거 0~4(7일 4·14일 3·30일 2·60일 1) + 숫자 확인 0~1 + 병목·전환 구조 0~3(경로 위 · 독립 이슈 2건+ · 상태 관측치 또는 공급사 3곳 이하) + 노출 순도 0~2(매출 비중 50%+ 2, 20%+ 1) − 주 기업 자신의 최근 반대 사실(최대 −2). 주가 전망이 아니다.
- **★ 규칙**: ★3 은 7점 이상(+ 30일 안 기업 직접 근거, ADR-0016 개정 3), 2점 이하는 ★1. 매 실행에서 손대지 않은 아이디어의 점수도 다시 계산해 ★ 가 규칙보다 높으면 내린다(올리지는 않는다 — 올리는 판단은 아이디어를 고쳐 쓰는 작업의 몫).
- **노출 순도**는 근거 id 가 있는 부문 매출로만 (추정 금지).
- **확인 일정**은 날짜·기준·방향을 가진 객체. 다음 실행이 적중(hit)·빗나감(miss)·의미 없어짐(void)을 근거와 함께 채점하고, 기한 지나 14일이 넘으면 '기한 지남'. 성적은 `/system` 에 쌓인다.
- 손대지 않은 아이디어의 점수와 채점은 `ideas.put_assessments` 로 매일 다시 쓴다 (`updated_at` 은 그대로 — 피드의 '바뀐 아이디어'에 끼지 않게).

### 2-4. 기회 발굴 (`wsj.ecosystems.scan`)
매일 아이디어 입력(leads)에 넣는다: 기업 소식은 있는데 아이디어가 없는 기업, 활동 많은 병목의 아이디어 없는 공급사, 설명 안 된 가격 급변(1개월 ±30% 또는 거래량 3배인데 14일 소식 없음), 노드 없는 이슈.

### 2-5. 스스로 개선하는 고리
- **매일** (`docs/agents/daily-ideas.md`): 수집 실행 → 원문 확인 → 관측치 → 아이디어·채점 → 판단 갱신.
- **매주** (`docs/agents/weekly-improvement.md`): `health`(시스템 점검) + `scan` + 출처 도달 점검(`source-probe` 워크플로) → 고칠 일 5개 → 근거를 직접 열어 확인한 그래프 패치·별칭·관측치 → PR → CI.
  - **데이터 PR**(`research/`, `apps/web/src/data/`, `graph_patches/`)은 CI 통과 시 스스로 병합한다.
  - **코드·워크플로·마이그레이션·작업 지침(docs/agents)** 이 바뀐 PR 은 사람이 병합한다 — 매일 돌아가는 파이프라인과 비용, 그리고 자기 지침을 스스로 바꾸지 않게.
- 개선 기록은 `research/improvement_log.json` → `/system` 의 "스스로 고친 기록".

### 2-6. 화면
- 카드: 근거 점수 · 이미 움직인 폭 · 다음 확인(날짜·기준). 표에 근거 점수 열.
- 상세: '판단' 절 — 점수 내역 막대, 노출 순도, 병목 상태 관측치, 이미 움직인 폭, 걸린 병목. 확인 일정은 상태(확인 전·확인됨·빗나감·기한 지남)와 함께.
- `/bottlenecks`: 병목마다 최근 이슈·상태 관측치·길목의 상장 공급사(가격 맥락, 아이디어 유무).
- `/system`: 고칠 것 · 수집 상태 · 커버리지 · 판단 성적 · 스스로 고친 기록.

### 2-7. DB (0021)
`investment_ideas.assessment`, `put_ideas` 가 assessment 저장, `put_assessments`, `put_observations`, 뷰 `v_price_context`·`v_collector_runs`·`v_indicator_registry`, `v_investment_ideas` 끝에 assessment. 적용 전에도 파이프라인·웹은 돈다.

## 3. 결과와 비용
- LLM API 비용 변화 없음 (판단·관측치·개선은 요금제 안의 예약작업). Actions 는 공개 저장소라 무료, 가격 수집으로 실행이 10~15분 늘어난다.
- 위험: 무료 비공식 가격 출처(Nasdaq API·Naver·Tencent·Kabutan)는 막힐 수 있다 → 시장별로 실패를 기록하고 점검이 잡는다. 스스로 병합은 데이터 경로로 제한했다.
- 남은 것: 유럽·인도·캐나다 가격 출처, 한국 DART 키, 관세청 품목별 수출, 일본 METI 생산 통계, 실적 발표 자료에서 부문 매출 자동 추출, 아이디어 유형별 적중률로 점수 가중치 조정.
