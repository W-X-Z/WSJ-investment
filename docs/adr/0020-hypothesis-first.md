# ADR-0020: 가설 우선 — 근거는 문이 아니라 시험 도구

상태: accepted (2026-10-29). 사용자: "오히려 추정 기반, 즉 가설을 잘 세울 수 있는 시스템이 되어야 돼."

## 문제
ADR-0016·0017 의 규율("숫자는 입력에 있는 것만", "추정 금지", 단계마다 근거 id, ★3 은 기업 직접 근거)은 LLM 이 뉴스를 받아쓰게 만들었다.
그 결과 기존 아이디어 11건은 수주·실적이 이미 난 기업(시장이 아는 것)이거나, 구조 추론뿐인데 추론을 적지 못해 비어 있는 가설이었다.
이 시스템의 목적(ADR-0017 개정 2, 0019)은 기술·산업 변화의 **다음 고리**를 시장보다 먼저 짚는 것이고, 그것은 본질적으로 추정이다.

## 결정
1. **아이디어 = 가설**: "변화 X(최근 사실)가 경로 P 를 타고 기업 C 의 숫자를 N분기 안에 Y 만큼 바꾼다 — 시장은 아직 그렇게 보지 않는다".
   좋은 가설의 조건(중요한 순): 구체적 · 대담(시장 미반영) · 반증 가능(날짜 있는 예측) · 설명력(지금 보이는 사실들을 한 논리로). 근거가 적어도 넷을 갖추면 쓴다.
   근거가 많아도 시장이 다 아는 이야기는 쓰지 않는다 (confirmation 유형만 예외).
2. **추론은 허용이 아니라 요구**: chain 의 추론 단계는 근거 없이 "(추론)" 으로 쓴다(사실 단계 1개 이상). anticipation.effect 는 basis 만 있으면 추정으로 받는다(`estimated`).
   가치평가의 가정은 사실(근거 id)과 추정(basis)을 구분한다(ADR-0019 보완). 검증기는 가설을 막지 않고 형식·산수·사실 표시만 본다.
3. **검증은 예측으로**: watch = 가설에서 도출한 예측 2~3개 + 반증 조건 1개(direction=weaken). 예측의 크기는 가설의 숫자(effect·lead_quarters)와 맞아야 한다.
   다음 실행이 날짜가 온 예측을 채점(hit/miss)하고, 그 기록이 ★ 를 움직인다.
4. **★ = 검증 단계**(확신이 아니다): ★1 가설(예측만) · ★2 부분 확인(예측 1개 적중 또는 기업 직접 근거) · ★3 확인(기업 공식 숫자 또는 적중 2개+).
   모든 좋은 가설은 ★1 에서 시작한다. 기존 규칙(★3 은 30일 안 직접 근거, 근거 점수 7+)은 ★3 의 문턱으로 그대로 둔다.
5. 화면: '논리' → '가설의 논리'(추론 단계는 색으로), '지켜볼 것' → '예측'. ★ 툴팁에 검증 단계.
