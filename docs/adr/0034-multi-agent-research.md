# ADR-0034: 멀티 에이전트 리서치 — 선별·오케스트레이터·역할 에이전트, 세 가지 저장 구조

- 날짜: 2026-11-08
- 상태: 채택 (일부 결정 대기 — 아래 '대기')
- 관련: ADR-0028(단서·해석·아이디어), ADR-0029(목적·방향만), ADR-0030(원본 입력·이어받기), ADR-0032(그 자리에서 판단), ADR-0033(산업을 정하지 않는다)
- 지침: `docs/agents/v2/`

## 배경 (2026-11-05~08)
- 아침 사슬(수집 → 해석 → 보강 → 리포트)은 단서는 많이 모으지만(단서 9,522건) 깊게 파는 쪽이 얇았다(조사 스레드 24개). 가치평가 테이블은 10/29 이후 멈췄고 지금 아이디어 테이블과 연결되지 않았다. 재무는 매출·영업이익·순이익뿐이라 순현금·희석주식 수를 매번 원문에서 찾았다.
- 11/5~6 수동 조사에서 "변화가 없었을 때 대비 증분"을 계산하자(선거 데이터센터 이전 8GW) 직관과 정반대 결론(증분 ≈0)이 나왔고, 같은 숫자(Bloom 연 5GW, PJM 상한)를 조사마다 다시 찾았다. 하위 에이전트가 결과를 남기지 않고 끝난 일이 세 번 있었다.
- 사용자(11/07): 데이터 파이프라인은 유지하고, 선별 에이전트를 신설하고, 초기 아이디어·펀더멘털·시장 산업·밸류에이션·가설검증·투자매력도 에이전트를 오케스트레이션하는 구조로 전면 개편한다.

## 결정
1. **역할 에이전트와 오케스트레이터 (11/07).** 선별(API) → 오케스트레이터(구독 예약 작업)가 초기 아이디어 → 시장·산업 ∥ 펀더멘털 → 밸류에이션 → 가설검증 → 투자매력도를 하위 에이전트로 부른다. 가설검증은 앞 단계의 결론·★를 받지 않는 별도 맥락이다. 계산(재무 정규화, 역산 DCF, 피어 배수, 증분, 주가 반응·동조 정도)은 코드 도구가 맡는다.
2. **아이디어는 스냅샷, 추적하지 않는다 (11/07).** 발행한 아이디어를 계속 모니터링하지 않는다. 다시 볼 일은 새 사건으로 들어와 새 리포트가 된다.
3. **지식은 다시 쓴다, 신선도는 꺼낼 때 확인한다 (11/07).** 산업 리포트 7일/30일, 기업 리포트 섹션별 90일, 원천 사실의 기준일. 재무 숫자는 코드가 최신으로 유지한다. 사건마다 전부 다시 계산하는 무효화 구조는 두지 않는다.
4. **항상 결론을 낸다 (11/07).** 애널리스트처럼 그 시점 데이터와 근거로 판단한다. 결론 = ★1~5와 한 줄 판단. 보류·막힘·관찰은 없다. 확인 못 한 부분·빠진 분석은 리스크 안에서 다루고 ★를 낮춘다. 리포트의 고정 칸은 결론뿐이고 나머지 구성은 내용에 맞게 쓴다('가장 약한 고리' 같은 고정 칸 이름은 두지 않는다).
5. **저장 구조는 셋 (11/07).**
   - 원천: `ideas.clues`(+본문). 바깥에서 들어온 것만, 에이전트가 찾은 원문 포함. 원문에서 뽑은 사실은 그 행의 `facts` JSON. 재무 공시 숫자도 공시 행의 사실.
   - 산업 그래프: `core.graph_*`. 산업 구간 노드를 더해 전방·후방·참여·공급·경쟁·소유를 잇는다. 기업 노드가 기업 기준표다. 관계 종류·숫자 항목은 고정하지 않는다.
   - 리서치 리포트: `research.reports`. AI가 계산·해석·판단한 모든 것(선별·산업·기업·아이디어·검증).
   - **별도 근거(claims) 테이블을 두지 않는 이유:** 사실은 늘 자기 출처 행에 붙어 있어야 출처 추적이 자연스럽고, 추적을 하지 않으니 사실 버전 관리가 필요 없다. 같은 사실이 여러 원천에서 엇갈리기 시작하면 그때 떼어낸다.
   - 가격·상장사 목록·환율·금리는 지식이 아니라 조회 도구다. 실행 기록은 예약 작업 이력과 리포트로 충분하다.
6. **투자 기간: 1년 내외 엑시트 (11/08).** 밸류에이션은 12개월 시나리오 가치와 그 안의 계기를 중심으로, DCF·역산은 교차 확인으로 쓴다. 기존 목표(1년 안팎 2~3배)는 유지.
7. **실행은 혼용 (11/08).** 선별처럼 자주 돌고 정형화된 일은 API(GitHub Actions, `ANTHROPIC_API_KEY`) — 하루 약 $0.7~1.9 추정(Haiku 1단계 + Sonnet 2단계 기준, 단서 하루 1,200건). 오케스트레이터와 웹 조사·판단이 긴 일은 구독 예약 작업. 기존 수집기는 GitHub Actions 그대로. Anthropic Managed Agents(베타, cron 예약·실행당 비용 상한)는 API 쪽 대안으로 검토한다.
8. **노션은 읽기용 사본과 입구 (11/06~08).** 원본은 Supabase. 노션 게시가 실패해도 결과는 남는다. 대상 DB 매핑은 `docs/agents/v2/notion.md` 한 곳에 둔다.

## 나중에 정리하는 것
- 아침 사슬(해석·보강·검토자·리포트 예약 작업)은 오케스트레이터가 파일럿을 통과한 뒤 종료한다.
- 구 리포트 계열 테이블(`ideas.opportunities`, `valuations`, `predictions`, `briefs`, `theses`, `issue_hypotheses`, `path_research` 등)은 쓰기를 멈추고 옮긴 뒤 legacy 로 보낸다. 웹이 이 테이블의 뷰를 읽고 있어 웹 결정과 함께 한다.

## 대기 (사용자 결정 필요)
- 노션 5개 DB 단순화안(원천 자료·산업·기업·투자 아이디어·조사 요청) 승인 — 그 전까지 notion.md 는 11/06 구조에 게시한다.
- 웹사이트: 기능 동결 유지 / 내리기.
- 그래프 원본 위치: DB / GitHub JSON.
- 외부 리서치 리포트(증권사 등)를 원천으로 받을지와 경로.
- 파일럿 가설 2개(제안: 러시아산 농축 금지 → 2028~30 서방 농축 부족, 우라늄 장기가 상승과 우라늄주 괴리).
- API 월 비용 상한.

## 하지 않는 것
- 발행한 아이디어의 갱신·점검일 관리.
- 확률·기댓값 숫자.
- 계산식·관계 종류·테이블 세부를 파일럿 전에 고정하기 — 같은 계산이 반복되면 그때 코드로 굳힌다.
