# 노션 (N8 · N24) — 읽는 곳이자 심층 요청 입구

원본은 Supabase. 노션 게시가 실패해도 결과는 남고 다음 실행이 다시 게시한다. 두 DB 는 'WSJ Investment · 투자 리서치' 페이지 아래에 있다.

| 무엇 | DB | data source | 제목 칸 |
|---|---|---|---|
| 1·2단계 후보 | 아이디어 후보 | `collection://dba688f2-3a3a-49fa-8562-5bc4a59053a4` | 아이디어 |
| 3단계 결과 | 리서치 리포트 | `collection://3fa1fd6e-dd00-47ef-a094-f38e54a9c480` | 제목 |

## 아이디어 후보 (N8)
- 최근 `candidates:` 보고서의 후보마다 한 페이지(같은 '후보 ID' 가 있으면 새로 만들지 않는다).
- 칸: 아이디어(헤드라인) · 종목 · 시장(미국/한국) · 사건 · 경로 · 축(병목/대체/시장 확대/협상력/기타) · 크기(대/중/소) · 역할(수혜/피해) · 시총(USD) · 사건일 · 상태 · 선택 이유 · 후보 ID.
- 상태: open → 후보, selected → 선택, requested → 심층 요청, done → 완료, dropped → 제외.
- 사용자가 '심층 요청'을 체크했는데 상태가 '후보'·'선택'이면 `monitor mark <후보 ID> --status requested` 후 상태를 '심층 요청'으로.
- 본문은 쓰지 않는다(메커니즘 한두 문장만 있으면 경로 칸으로 충분하다).

## 리서치 리포트 (N24)
- 칸: 제목 · ★(★1~★5) · 종목 · 시장 · 판단(verdict) · 기준일 · 시총(USD) · 리포트 ID · 후보 ID.
- 본문: report-template.md 순서대로 요약 박스 → 결론 → 본문 절. 주가 이슈 절 위에 차트 PNG 를 붙인다. 숫자 옆 출처는 원문 링크.
- 본문 끝에 '사용자 메모' 제목만 비워 둔다. 에이전트는 그 아래를 쓰지도 고치지도 않는다.
- 게시 후 후보 페이지의 '리포트' 관계와 상태 '완료'를 채운다. 페이지 URL 은 리포트 저장 JSON 의 notion_url 로 다시 저장한다(`deep save`).

## 하지 않는 것
DB 속성·선택지 바꾸기, 아카이브(2026-11-06 이전 구조) 건드리기, 사용자 메모 고치기.
