# 노션 게시

노션은 리포트의 **읽기용 사본**이자 사용자의 메모·조사 요청 입구다. 원본은 Supabase(`research.reports`, `ideas.clues`)다. 노션 게시가 실패해도 Supabase 결과는 남고, 다음 실행이 다시 게시한다.

## 대상 DB (현재 프로젝트 페이지의 11/06 구조)
사용자가 5개 DB로 줄이는 안(원천 자료·산업·기업·투자 아이디어·조사 요청)을 아직 승인하지 않았다. 승인되면 **이 표만** 바꾼다.

| 무엇을 | 노션 DB | data source | 제목 칸 | 채우는 칸 |
|---|---|---|---|---|
| 아이디어 리포트 (`kind = idea`) | 가설·초기 리서치 | `collection://3cf70b10-c5ff-4e77-a092-c53390a86566` | 가설 | 핵심 변화, 변화 유형, 분석 기준일, 현재 판단(아래), 초기 판단(★ + 한 줄 판단), 관련 기업, 산업·매크로 리포트, 핵심 근거, 아이디어 키(report_id) |
| 기업 프로필 (`kind = company`) | 기업 리포트 | `collection://fe8a5748-e12c-48c8-8e73-1c725c6f0736` | 기업명 | 티커, 시장, 산업, 핵심 제품, 사업 요약, 핵심 판단, 보고서 기준일, 핵심 근거, 출발 가설, 기업 키(report_id) |
| 산업 브리프 (`kind = industry`) | 산업·매크로 리포트 | `collection://c3dad903-80d3-4593-8ac5-3712d19d54c8` | 리포트 | 분석 유형(산업·기술 / 매크로·정책), 기준일, 핵심 결론, 영향 기간, 관련 기업, 연결 가설, 핵심 근거 |
| 인용한 원천 | 데이터 파이프라인 | `collection://f9733440-2257-488b-baa1-d983b75d87c9` | 자료명 | 자료 유형, 수집 채널, 출처 성격, 발행일, 원문 URL, 핵심 사실, 원본 키(clue_id), 선별 상태 '분석 연결', 연결 가설, 관련 기업 |
| 조사 요청 (읽기·상태 변경) | 조사 요청 | `collection://8078489b-cf90-434d-9992-c555f2360657` | 조사 질문 | 상태(접수 → 조사 중 → 완료), 결과 요약, 관련 가설 |

- 아이디어의 '현재 판단' 칸은 기존 선택지에 맞춘다: ★4~5 → 매력적, ★3 → 조건부 매력, ★2 → 가격 부담, ★1 → 가설 기각. ★ 숫자는 '초기 판단' 칸 첫머리에 `★3 — 한 줄 판단` 형태로 함께 쓴다.
- '다음 점검일', '판단 변경일', '변경 요약', '모니터링' 단계 같은 추적용 칸은 채우지 않는다(발행 후 추적 없음).
- 인용한 원천만 노션에 올린다. 수집한 단서 전부를 올리지 않는다. 같은 원본 키가 있으면 새 페이지를 만들지 않고 연결만 한다.
- 조사 요청 유형 매핑: 신규 가설 → 새 아이디어, 추가 검증·가치평가 → 해당 리포트 보완 후 새 리포트, 사실 정정 → 원천 사실 정정(발행된 아이디어는 고치지 않고 그 사실을 쓴 아이디어 목록을 결과 요약에 적는다).

## 페이지 본문
- 리포트 `body` 를 그대로 옮긴다. 맨 위는 결론(★·한 줄 판단·기준일), 나머지 절은 리포트 순서대로.
- 숫자 옆 출처는 원문 링크로. 계산값은 '계산값'이라고 표시한다.
- 본문 끝에 '사용자 메모' 제목을 비워 둔다. 에이전트는 그 아래를 쓰지도 고치지도 않는다.
- 게시 후 페이지 URL을 `research.reports.notion_url` 에 넣는다.

## 하지 않는 것
- DB 스키마(속성·선택지)를 바꾸지 않는다. 아카이브(2026-11-06 이전 구조)를 건드리지 않는다.
- 기존 페이지를 덮어써서 판단을 바꾸지 않는다 — 새 사건이면 새 페이지.
