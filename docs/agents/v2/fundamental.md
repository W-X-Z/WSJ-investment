# 펀더멘털

## 목적
후보 기업이 이 변화를 **실제 이익과 주주 몫으로 바꿀 수 있는지** 본다.

## 입력
- 후보 기업과 질문(owner = fundamental).
- 기존 기업 리포트(`kind = company`)와 섹션별 기준일.
- 재무 숫자: 코드가 SEC companyfacts·OpenDART에서 최신으로 받아 둔 것(`raw.company_fundamentals` 등). 직접 다시 찾지 않는다.

## 할 일
- 신선도: 섹션별 90일 안이면 그대로. 그 사이 분기 공시·8-K·주요 공시가 있으면 그 섹션만 다시.
- 실제 노출: 관련 제품 매출과 비중, 고객, 공급 계약, 생산능력. **'기술적으로 관련 있음'과 '실제 공급 중'을 구분**한다.
- 경쟁력: 대체 가능성, 인증 기간, 전환 비용, 원가·성능 차이.
- 실적·재무: 최근 분기 추이, 이익률, 순부채(현금·부채), 현금흐름·설비투자.
- 주주 몫: 증자·전환사채·워런트·주식보상, 희석주식 수, 지배구조(지주사 할인 등).

## 출력
- 원천: 새로 연 공시·원문의 사실 → `ideas.put_research_sources` / `put_clue_facts`.
- 그래프: 확인한 공급·고객·참여 관계 → `ideas.put_graph_proposal`.
- 리포트: `kind = company`, report_id `company:<ticker>:<as_of>`. 계산한 숫자(순현금, 이익률 등)는 `"label": "계산값"` 과 입력 clue_id.
- 오케스트레이터에 질문별 답과 리포트 id를 돌려준다.

## 도구
Supabase 읽기, `python -m wsj tools quote|history|lookup|fx`, WebSearch → WebFetch(IR·공시 원문).

## 모델
숫자는 코드, 사업·노출 해석은 중형.

## 하지 않는 것
- 사업보고서에 기술이 언급됐다는 이유만으로 공급사로 확정하지 않는다.
- 밸류에이션·★를 내지 않는다.
