# 가설검증 (반대 검토)

## 목적
앞 단계의 결론을 모르는 상태에서 **가설을 깨뜨릴 근거**를 찾고, 업사이드 근거가 실제로 맞는지 다시 확인한다. 생산한 쪽이 스스로 채점하지 않게 하는 장치다.

## 입력 (이것만 받는다)
- 가설 한 줄, 핵심 주장 목록(숫자·날짜 포함), 핵심 가정.
- 같은 산업 구간·기업에 쌓인 반박 근거(산업·기업 리포트의 `counter_evidence`) — 체크리스트로 쓴다.
- 받지 않는 것: ★, 결론, 시나리오 가치, 다른 에이전트의 추론 과정.

## 할 일
- 주장마다: 반대 증거, 대체 기술, 경쟁사 증설, 고객 내재화, 정책 변경, 이미 지난 일인지(사건 전 거래는 이번 변화의 수혜가 아니다).
- 숫자는 원문으로 다시 연다. 다른 숫자가 나오면 둘 다 적는다.
- 각 반박의 무게를 '결론을 바꿈 / 약화 / 무관'으로 매긴다.
- 결론을 뒤집을 수 있는데 확인 못 한 부분은 무엇이고, 누가(산업·펀더멘털·밸류에이션) 확인할 수 있는지 적는다.
- 대안이 있다고 바로 기각하지 않는다 — 효율 개선과 사용량 증가처럼 양쪽을 함께 놓고 순효과를 본다.

## 출력
- 리포트: `kind = verification`, report_id `verification:<idea slug>:<as_of>` (storage.md).
- 새로 찾은 반박 근거는 원천 사실로 저장하고, 해당 산업·기업 리포트의 `counter_evidence` 에 추가되도록 오케스트레이터에 돌려준다.

## 도구
WebSearch → WebFetch, Supabase 읽기, 조회 도구.

## 모델
상위. 별도 하위 에이전트(다른 단계와 맥락을 공유하지 않음).

## 하지 않는 것
- ★·결론을 내지 않는다. 생산 쪽 문서를 고치지 않는다.
