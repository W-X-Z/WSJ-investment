# 워크로드 → 하드웨어 계수표

`workload_hardware.json` + `python -m wsj.ecosystems.coefficients` (ADR-0026 T-4).

테제가 "에이전트가 메모리를 더 쓴다" 에서 멈추지 않고 **얼마나** 를 말하려면 두 축을 같은 표에 놓아야 한다:
- **사용량** (토큰/월, 질문당 출력 토큰, 세션 컨텍스트 길이) — 늘어난다.
- **토큰당 강도** (토큰당 KV 바이트, 가중치 바이트, 정밀도) — 구조(GQA → MLA → 교차층 공유)와 정밀도(BF16 → FP8 → FP4)로 줄어든다.

## 첫 계산 (2026-10-30)
| | 값 | 근거 |
|---|---|---|
| Google 토큰/월 | 480T (2025-05) → 3.2Q (2026-05), **연 6.7배** | blog.google I/O 2026 (확인) |
| DeepSeek 계보 토큰당 KV | 35,136B (V3 FP8, 2024-12) → **890B** (V4.1-Flash 전역 KV, 2026-09), **연 0.12배** | HF config · vLLM 블로그 2026-10-23 (확인) |
| 순 KV 트래픽 방향 | **연 0.77배** — 압축이 사용량 증가를 앞선다 | 위 둘의 곱 |
| 희소성 지수 | 2026-09: +4, 2026-10: +2 (가격 인상 예고·접근 제한·시간대 가격) | 에이전트 보고, 재확인 전 |

읽는 법: 이것은 **메모리 테제에 대한 반증 방향의 숫자**다. 다만 (1) 압축 계보가 DeepSeek 한 랩이고 (2) 890B 는 "global" KV 만이라 로컬 KV 를 빼고 있을 수 있으며 (3) 상주 메모리는 처리 토큰이 아니라 "동시 세션 × 컨텍스트 × 바이트" 에 비례하고 에이전트 세션은 대부분 유휴라 HBM 이 아닌 DRAM·SSD 계층에 산다 — 그래서 "HBM 용량 수요" 에는 약하고 "용량 계층(DRAM·CXL·SSD)" 에는 덜 약하다. vLLM 원문도 디코드 시간의 62% 가 MoE(가중치 읽기 = HBM **대역폭**), 13% 가 어텐션이라고 한다 — 압박이 용량에서 대역폭으로 옮겨간다.

## 갱신 (토요일 테제 작업 1부)
- 새 프런티어 모델이 나오면 config(또는 서빙 엔진 블로그)에서 토큰당 KV 를 한 행 더한다. 원문을 열었으면 `verified`, 아니면 `agent_reported`.
- Google·OpenAI·Microsoft 등의 토큰 처리량 발표를 `usage_series` 에.
- API 가격 변경 중 인상·배급·시간대 가격·인하를 `scarcity_events` 에 (인하는 음수).
- `python -m wsj.ecosystems.coefficients` 의 "순 KV 트래픽 방향" 이 1 을 넘나드는지를 메모리 테제의 드라이버로 본다.
