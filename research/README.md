# 과거 텐배거의 '발견 가능한 순간' 역추적 (2026-10-26)

## 목적과 검증 질문
- 수익률을 사후 설명하는 대신, **그 시점에 공개된 사업 변화와 숫자만으로 직관적인 가설을 만들 수 있었는가**를 기록한다.
- 급등 구간 전체 수익률과 **사건 공개 후 매수 시도 시의 사후 수익률**을 분리한다.
- 초기에 성공 사례 5개와 반례 2개를 연구했다. 지금은 아이디어 탐색이지 백테스트가 아니다.

## 시점 고정 원칙
1. 가설 작성 시 공시/기사/회사 발표의 **실제 공개 날짜**를 먼저 확정한다. 연간 보고서에 나중에 추가된 사실을 최초 시점의 근거로 쓰지 않는다.
2. 발표 이후 첫 확인 가능 거래일의 분할조정 종가를 참고 진입 가격으로 쓴다. 종가 체결을 보장하지 않는다.
3. 평가 종료 날짜는 사후 선택이다. 이 종가 또는 특정 최고 종가를 실전 청산가격이라고 주장하지 않는다.
4. 각 케이스는 가설, 공개된 데이터, 반대 가설, 추가로 확인했어야 할 데이터, 반증조건을 구분한다.
5. 동일 기준으로 아직 성공하지 않은 후보를 모두 수집하지 않았으므로 전략의 적중률, 재현 가능성, 실제 투자수익은 추정할 수 없다.

## 잠정 인사이트 (아직 통계적 발견 아님)
- **사업 변화가 직접 확인 가능한 중간 지표**가 있는 사례는 투자 가설을 만들기 쉬웠다: 매장 입점 → 기존점 판매, AI 모델 개선 → 광고주 지출, 서버 수요 → 매출/주문, 비용 절감 → 현금 유출 둔화, 통신 기술 → 고객 계약/허가.
- **시장 규모(TAM) 대신 임계점에 주목**: 기존보다 성장이 얼마나 가속됐나, 실제 수익이 발생했나, 외부 고객이 돈/계약으로 확인해줬나.
- **거래 신호는 보조 증거**: 거래량 급증, 주가 돌파, 내부자 매수는 가설을 발명하지 못하며 원천적 사업 변화를 확인한 뒤 타이밍 도구로 쓴다.
- **시나리오 확률 추정보다 관측 가능한 다음 이벤트**가 유용하다. '이번 분기에 무엇을 확인하면 가설이 강화되거나 깨지는가'가 우선이다.

## 기존 WSJ-investment에 적용할 4개 리서치 워크플로
1. **발견(광범위)**: 신제품, 정부 인허가, 산업 투자 증가, 구매 계약, 유통망 진입, 주요 고객 도입, 비용 구조 변화를 공개 자료에서 발견한다.
2. **번역(가설)**: '무엇이 변하고 -> 누가 돈을 내며 -> 회사의 어떤 재무 항목이 -> 언제 바뀌는가' 1문장으로 생성. 답하지 못하면 후보 보류.
3. **검증(반증 포함)**: SEC/XBRL, 계약 원문, 고객사의 투자계획, 경쟁사 지표를 서로 대조; 자금조달과 희석 위험 평가. 미확인 변수는 데이터 갭으로 분리.
4. **추적(행동 트리거)**: 다음 실적·제품·계약·규제 이벤트와 사업 KPI를 캘린더로 관리. 실제 매매는 사용자 판단.

## 추가 정량 검증 계획
- **1단계 데이터 보강:** 5개 사례의 일봉 OHLCV(분할/상장폐지 조정), 발표 시간(장전/장후), 당일·다음 날 거래가능 가격. 정해진 시점 이후 고정 3/6/12/24개월 수익률 및 최대낙폭 산출.
- **2단계 반례 확장:** 동종·유사 규모 기업과 실패/미실현 기업을 1:2 이상으로 매칭. 2020~2025 당시 전체 상장 종목을 모집단으로 만든다.
- **3단계 블라인드 실험:** 신호의 날짜 이전 정보만 조회하도록 강제한 후, 미래 12개월 성과를 모르는 상태로 가설 품질 평가. 결측·생존자 편향·상장폐지·거래 비용 반영.
- **4단계 실서비스 접목:** 기존 Supabase에는 원문 출처·공개일·signal/trigger/evaluation을 별도 저장, Python 분석은 GitHub Actions에서 실행, Vercel은 케이스별 사건 타임라인·가설·근거·후속 점검을 표시. 1차 연구에서는 운영 DB를 변경하지 않는다.
- **성공 기준:** 높은 역사 수익률이 아니라 실제 관측 가능했던 가설의 재현 가능성, 허위 양성 빈도, 신호 공개 후 실현 가능한 수익, 후속 검증 가능성을 비교한다.
