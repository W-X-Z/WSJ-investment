# 해석 지침 (playbook) — 암묵지를 쌓는 곳 (ADR-0028)

해석 작업(`docs/agents/daily/interpret.md`)이 단서를 읽기 전에 이 폴더를 읽는다. 화면에는 나오지 않는다.

- `lenses.md` — 생각하는 순서 8가지 (매출 분해 · 병목과 이익 이동 · 대체 · 파이 · 단서의 다른 설명 · 부족기 증폭 · 시장 기대 · 누가 지키나).
- `patterns/*.md` — 여러 해석에서 반복된 메커니즘에 이름을 붙인 카드. 규칙이 아니라 "이런 모양을 전에 봤다" 는 기억이다.

## 패턴 카드 형식
```
# <이름>
- 언제: 어떤 부품·시장·국면에서 나타나나
- 메커니즘: 왜 그렇게 되나 (2~4문장)
- 단서로 보이는 모습: 어떤 작은 단서가 이 패턴의 시작인가
- 반대 신호: 이 패턴이 아니라는 증거
- 사례: 아이디어 key·날짜·결과(사용자가 확인한 메모가 있으면 함께)
- 관련 노드: 그래프 노드 id
```

## 누가 고치나
- 해석 작업: 새 사례를 기존 카드의 '사례' 에 더하고, 새 메커니즘이 보이면 카드 초안을 PR 에 넣는다 (`research/` 안이라 스스로 병합).
- 주간 반성(주간 개선 작업): 한 주의 해석을 읽고 카드를 합치거나 고치거나 반대 신호를 더한다.
- 사용자의 지적이 가장 강한 입력이다 — 지적이 들어오면 해당 카드를 먼저 고친다.
