# 사용자 지적 — 사용자가 중요하게 여긴다고 말한 것

대화에서 사용자가 말한 것을 날짜와 함께 한 줄씩 적는다. 규칙이 아니라 방향을 이해하기 위한 기록이다 — 정리된 방향은 `docs/agents/daily-ideas.md`.
줄 끝의 `→ 반영:` 은 그때 어느 문서를 고쳤는지의 흔적이다. 2026-10-31 개정으로 지침이 목적·방향 중심으로 바뀌어, 그 전의 '§' 참조는 더 이상 맞지 않을 수 있다.

- 2026-10-30: 공시는 이미 알려진 사실 — 공시보다 작은 이슈(출시·협약·샘플·초도 수주·채용·전시회)를 먼저 본다. → 반영: lenses.md 수집 원칙, interpret.md §2
- 2026-10-30: 빈도·점수 누적 같은 정량 규칙보다 해석이 중요하다. → 반영: README.md, ADR-0028
- 2026-10-30: 제목은 '[원인]에 따른 [대상] [변화]' 명사형 (예: HBM 고집적화에 따른 유리 인터포저 수요 확대). → 반영: docs/agents/writing.md
- 2026-10-30: 공시는 후행성 데이터 — 뒤로 미룬다 (DART 키 등록·공시 API 확대 보류. 해석은 공시를 맨 나중에, 기존 아이디어 갱신용으로만). → 반영: interpret.md §2, BACKLOG A-7
- 2026-10-30: 드러난 문제를 하나씩 고치는 데 초점을 두지 말고, 고쳤을 때 목표(시장보다 먼저 큰 기회를 찾는 것)에 가까워지는지를 먼저 본다. 목표에 닿지 않는 문제는 굳이 고치지 않는다. → 반영: weekly-improvement.md §2 첫 질문
- 2026-10-30: 목표는 텐배거가 아니라 1년 안팎에 2~3배면 충분하다. → 반영: writing.md ★ 기준(크기 + 1년 안의 계기), 아이디어 3·4번 문장
- 2026-10-30: 한국보다 미국에 집중 — 한국 소형주는 내부 자료가 내부자·애널·기관에 먼저 퍼져 공개 데이터로 앞서기 어렵다. 미국이 데이터 기반 탐색에 공평하다. → 반영: interpret.md §3.4(미국 먼저, 아시아 업계지는 미국 회사의 고객·공급사 창), daily-ideas.md, 기술 흐름 단서 정렬
- 2026-10-30: 이미 알려진 증거(수주·실적)보다 기술·수요·시장을 예측하는 전략이 개인 투자자에게 맞다. 숫자가 나올 때는 이미 늦다 — 위험은 감수한다. → 반영: writing.md(아이디어 4·5번 문장: 채택의 첫 신호, 틀렸다고 볼 신호·확인 시점 / ★ 기준), interpret.md §2 첫 항목·§3.5·§3.6, daily-ideas.md, BACKLOG A-11(예측 장부)
- 2026-10-31: 뉴스보다 기술 연구 발표·Federal Register 같은 원본이 낫다 — 뉴스는 원본 데이터를 옮겨 쓴 것이고 복제된다. → 반영: interpret.md §1 '원본 먼저', BACKLOG A-12
- 2026-10-31: 단서가 최초 이슈인지 전에도 있던 이슈인지 본다 (과거 유사 이슈는 필수 조사가 아니라, 이미 반영됐는지 판단할 때 쓴다). → 반영: interpret.md §3.6
- 2026-10-31: '더 살펴봐야 한다'에서 멈추지 말고 결론까지 조사한다 (코딩은 끝까지 하면서 조사는 멈춘다). → 반영: interpret.md §2·§3.7 (날짜 없는 '확인 필요' 금지)
- 2026-10-31: 원천에서 시작하는 흐름은 좋다. 빠진 것은 이미 주가에 반영됐는지와 시총 대비 영향의 크기 판단. → 반영: interpret.md §3.6 (영향·반영·남은 여지 숫자), writing.md 아이디어 3·4번 문장과 ★ 기준, enrich.md §2, report.md §1
- 2026-10-31: 시장이 이미 알고 주가에 반영됐는지 분석하는 것과 정확한 멀티플로 주가를 계산하는 것은 전혀 다르다 — 반영 여부는 증거(언제부터 알려졌나·주가 반응·증권사 언급·실적 발표 언급)로, 영향은 회사 크기에 비해 대략의 단위로 본다. 멀티플 주가 계산은 하지 않는다. → 반영: interpret.md §3.6, writing.md 3·4번 문장과 ★, enrich.md §2, report.md §1 (바로 위 항목의 '남은 여지' 계산을 대체)
- 2026-10-31: '알려졌으니 반영됐다'는 효율적 시장 가설에 기댄 판단이고 매크로도 빠졌다. 핵심은 시장이 무엇을 믿는지 보고, 데이터·온톨로지·추론·조사·과학적 연구로 그 믿음이 틀렸다고 말할 수 있는지다 (예: 정책은 알려졌지만 시장은 T1 의 수혜를 믿지 않는다 — 그 불신이 틀렸다면 기회). → 반영: interpret.md 머리말·§3.6(시장의 믿음 → 불신 이유를 가설로 검증, 알려졌다는 이유로 내리지 않음, 매크로 민감도 한 줄), writing.md 4번 문장과 ★, enrich.md §2, report.md §1, BACKLOG A-14
- 2026-10-31: 지침을 정하면 지침대로만 한다 — AI 성능이 높아졌으니 목적과 방향만 정하고 방법은 그때그때 판단하게 한다. 시장은 변수가 많고 늘 변해 한 번 세운 로직이 다른 사례에 맞지 않는다. 모든 과정에서 마찬가지. → 반영: ADR-0029, daily-ideas.md(목적·방향·꼭 지킬 것), 작업 문서 전부(맡은 일·재료·저장 방법만), writing.md, weekly-improvement.md, playbook README·lenses(참고 자료), PROMPTS.md
